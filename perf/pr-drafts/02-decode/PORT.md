# PORT.md for PR 2 (decode): map onto origin/master 4d4db90

Upstream layout: `megakernel/qwen38_mk.cu` (plain Q4_K_M engine; types Q4_K / Q5_K / Q6_K / Q8_0) and
`megakernel/qwen38_mixed.cu` (mixed-quant engine; adds IQ4_XS, `gemv_pairs_any`, `resid_any`, `ffn_gu_any`, `rows16`), each a
full copy of the engine (device code + `MKEngine::Impl` host code); GEMM headers `prefill_gemm.cuh` (plain) and
`prefill_gemm_mixed.cuh` (mixed); `prefill.cuh` is shared. #21 patched both files with identical hunks; so does every
change below ("both" = apply twice). Line numbers are origin/master's, plain / mixed.

This PR is independent of PR 1 and lands first. It carries 535e80c (moved from PR 1) and does not carry f58e21e (moved to PR 1).

Effort: S = under a day with gates, M = 1-3 days, L = a week or more.

## Things to check during the port

1. **Gate ordering**: land item 1 first. `attn_core_q8` and `MK_DA_ROUTE` assume whole-tile chunks and `ATT_BUCKET`.
2. **Per-function ptxas diff after each item** (our notes: a new caller of a shared `__noinline__` leaf can re-split registers
   in other callers; do not use `nvcc -cuda` as a check, it runs ptxas). Upstream's engines have different function sets, so the ptxas numbers in
   the commit messages will not carry over; use "no new spills in the hot loops" as the gate. Building `qwen38_mixed.cu` needs
   about 11 GiB of host RAM (upstream README), the plain engine less.
3. **KV formats**: upstream has fp16 and q8 only. `attn_core_q8` applies to `kvq8`. The `attn_core_q8m` low-bit variant,
   `MK_DA_Q4` and the per-slot `kvb[]` checks in our dispatch belong to PR 4; do not port them here.
4. **Plain-engine exactness**: our plain Q4_K_M gates for this set were KLD mixed byte-identical and ids identical at
   `-d 0 / -d 4`; the q8-cache long-context speed on Q4_K_M was not measured. Run the km-style bench
   (`notes/main/km/`) before quoting a plain-engine speedup.
5. **Turing**: the plain engine is the only Turing target. Items 1, 5, 6 (Ampere branches), 7 (Ampere branch), 8, 9 are
   architecture-neutral; item 2-4 are sm_80+ and need `#if !QWEN_MK_SM75`. Upstream's Turing build uses
   `-DQWEN_MK_SM75=1` and mirrors resource constants with `cuda_compat.cuh`; any new `constexpr` resource constant (e.g.
   `AQ_STG`, `AQ_NSK` for the new rings) must be defined identically for host and device passes under that macro.
6. **Tooling**: the exactness checks used `notes/dattn2/tinv_q8.sh` (q8 cache, 120K ctx; the older `notes/spec/tinv.sh` runs
   the fp16 cache at 8K and never exercises the q8 attention), KLD mixed + 32k against `~/kld/ud.ref` / `ud32k.ref`, and
   `bench/dattn_bench.cu` for bitwise partials.
